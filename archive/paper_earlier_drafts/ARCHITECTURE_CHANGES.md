# Changes to the original architecture

Original = the repo behaviour-cloning policy (`bev_policy/model.py`): 1-channel GitHub BEV (CNN) + 6-D scalar (MLP) -> `[steer, throttle]`.
See `figures/fig1_architecture.png`. Every row says what changed, why, the evidence, and its status. Figures are regenerated by `paper/make_figures.py` from result files in `paper/results/`.

| # | Change | Why (source) | Evidence | Status |
|---|--------|--------------|----------|--------|
| C1 | **Training: plain BC -> DAgger** with an IDM expert queried at the learner's own states | BC drifts off-distribution (ChauffeurNet, Ross et al. 2011) | Traffic 0.2, seeds 1000-1009: repo BC 0.10 success, DAgger models 0.30-0.60 (Fig. 3). n=10, wide CIs | Suggestive; confirm on n=40 fresh seeds |
| C2 | **BEV content: HD-map overlay** (route 0.5, boundary 0.8 per team spec) filled by a wrapper; GitHub `bev_state/` unmodified | GitHub BEV draws neither; spec Table 7; Roach puts route/lane in the BEV | `ov_*` vs `base_a` (Fig. 3, Fig. 4) | Suggestive (see C3) |
| C3 | **Scalar split (Roach-style):** lateral/heading/curvature move from the 6-D scalar into the BEV; scalar keeps speed, progress, goal (`ov_split`) | Roach; causal confusion (de Haan 2019): earlier ablation showed some scalars hurt | traffic 0.2: `ov_split` 0.60 vs `ov_both` 0.30 vs `base_a` 0.40 (n=10; CIs overlap) | Suggestive; needs more seeds |
| C4 | **Caution input c** (1-D branch -> 16 -> head) + caution-aware teacher (speed 30->20 km/h, gap 10->25 m) | RSS-style: speed/gap should follow perception limits | pending (`eval_caution`) | **Pending** |
| C5 | **c = c_auto(weather) = 1 - measured YOLO retention**; detector dropout at measured rates during training | Fig. 2: detections kept falls to 4% at rain 1.0, 27% at fog 1.0 | pending | **Pending** |
| C6 | Engineering: camera free-space mask cached in my env (bit-identical to `build_bev_grid` over 400 grids), BEV 42 -> 13 ms | speed | exact-equality test | Done |
| C7 | PPO fine-tuning of the DAgger base | standard | no gain (val 0.675 -> 0.675 at 120k steps); also confounded by rain->friction coupling in `env.py` | **Negative result**; not part of the method |

## Honest status of the claims
- Only C6 is fully verified. C1-C3 are supported by n=10 evaluations whose 95% intervals overlap; they are not yet claims.
- C4/C5 are the proposed contribution; no result yet. They will be reported whether or not they win.
- Weather has no dynamics effect anywhere in the new code (friction fixed at the MetaDrive default), per project rule; weather acts only through perception (detector dropout).

## Fair comparison protocol (for C4/C5)
Same fresh seeds (1010-1039), traffic 0.2, horizon 800, weather {clear, fog 1.0, rain 0.6, rain 1.0}, identical detector dropout, for: previous best `ov_split`, a no-caution control with identical data/architecture, ours at c = 0, c = 1, c_auto, and an upper bound with perfect perception. Wilson 95% CIs.
