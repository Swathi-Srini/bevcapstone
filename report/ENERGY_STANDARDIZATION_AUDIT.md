# Energy implementation audit

## Findings before recalculation

`bev_rl/energy.py` is the canonical source for estimated mechanical traction energy. It integrates signed inertial, aerodynamic, and rolling work in closed form under a linear-speed assumption for each step, clips negative step work to zero, and reports Wh/km from distance integrated over the same speed trace. It requires the live simulator mass and timestep. This is a mechanical-work estimate, not measured battery energy.

## Method suitable for the paper

We estimate mechanical traction energy per kilometre from the MetaDrive ego vehicle's longitudinal speed trace. For each decision interval, we assume speed changes linearly from (v_0) to (v_1), then compute inertial, aerodynamic, and rolling-resistance work in closed form. We use the simulator-reported vehicle mass (the current default vehicle is 1100 kg), (C_d=0.23), frontal area (A=2.22\,m^2), (C_{rr}=0.01), air density (1.225\,kg/m^3), and a flat road. Negative net work is clipped to zero at each step, with no regenerative braking. We divide summed positive work by distance integrated from the same trace and report Wh/km. This is an idealized mechanical traction-energy estimate; it is not measured battery energy and excludes drivetrain losses, auxiliary loads, and grade.

## Max-step evaluation protocol

The 500-step setting is a truncation limit, not an episode discard: the evaluator saves an outcome row when the limit is reached. For a longer route-completion window, run the separate weather batch with `--max-steps 1000`; keep this cap recorded because changing it changes the evaluation protocol. The PPO recalculation itself retains the original 500-step cap so its classifications remain comparable.
